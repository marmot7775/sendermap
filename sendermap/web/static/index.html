How it works

Evidence, not guesses

Every service on the map comes with the public records that show it: an MX host, an SPF include, a DKIM key, a bounce or tracking address, a verification token, a script on the website. You can check each one yourself.

How sure, in words

Receives your mail: mail for the domain is delivered there. Set up to send: records are in place for it to send as the domain. Likely sends: a signing key named for the service, or its script on the website. Account only: a trace of an account with nothing set up to send.

Beyond the main domain

Brands send a lot from subdomains such as email., bounce. or mg.. Sendermap finds them from common names and certificate logs, and maps each one.

Raw addresses, named

When SPF lists IP ranges instead of a service's name, Sendermap matches them against the ranges each service publishes, then against who owns the network.

Private by design

The server keeps no record of the domains you look up. Results are held in memory for ten minutes so a shared link opens instantly, then forgotten.

Open source

The engine, the vendor list and every matching rule are on GitHub. Run it yourself from the command line, on your own machine.
